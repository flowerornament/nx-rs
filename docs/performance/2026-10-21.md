# Detailed performance traces, 2026-10-21

Investigation: `nx-rs-gm7s`. Released binary: nx 1.5.46 at
`7f9a723a52052f5ad2e8f56b33716f39d5475c98`. Machine configuration tracing is
activated and published as nix-config `f9a61ae`; the richer collector/report in
this change is not yet released. The [measurement receipt](2026-10-21.json)
records identities, load, exact durations and artifact locations.

## What normal history shows

Ten retained operational upgrades on nx 1.5.44–1.5.46 had stage timings but
no detailed trace path. Three v1.5.46 observations illustrate why
neither totals nor version comparisons isolate a bottleneck:

| Stage | Targeted nx install, 09:09 UTC | Busy upgrade, 09:53 | Warm admission, 10:20 |
|---|---:|---:|---:|
| Complete command | 52.17s | 181.64s | 51.51s |
| Cache preflight | 18.68s | 97.21s | 0.35s |
| Homebrew upgrade | skipped | 51.97s | 13.49s |
| Rebuild | 26.16s | 3.34s | 22.23s |
| Build inside rebuild | 3.27s | 0.36s, already current | 0.08s |
| Starting 1-minute load / 18 CPUs | 22.99 | 116.74 | 48.52 |

These runs differ in inputs, package work and host conditions. They are not a
version speed comparison. The no-op shortcut works; the slow upgrade spent its
time before that shortcut.

## Complete traced rebuild

The user requested more detailed traces. An isolated config desk enabled
`programs.nx.tracing.directory = "${config.xdg.stateHome}/nx/traces";` and passed
`nix flake check --no-build`. The owner approved the already-prepared Ferry
v0.1.6 pin before it was activated together with tracing. A canonical
`NX_TRACE_PATH=… nx rebuild --timing` then completed successfully at config
`f9a61ae`.

The retained trace has 5,240 events, 252 matched Nix activities, no unfinished
activities and no unmatched stops. It ends with `complete: true` and exit 0.

| Interval | Duration | Scope |
|---|---:|---|
| Entire trace | 321.537s | Includes initial setup and final trace completion. |
| User `nix build` | 251.221s | Includes the following two overlapping inner scopes. |
| First inner Nix activity, type 10113 | 169.145s | Completes before realization starts; semantic name was dropped by the released collector. |
| Realization | 77.502s | Local derivation work and daemon coordination; not isolated compiler CPU time. |
| Passwordless fallback switch | 66.551s | Includes the following inner activity and required activation. |
| Root-side inner Nix activity, type 10113 | 54.454s | Before activation; its exact named work cannot be recovered from this trace. |
| Homebrew activation | 4.333s | Part of the fallback, not an additional top-level interval. |
| Wall time outside recorded commands | 0.033s | Residual, not a measurement of nx CPU time; command wrappers are inside command intervals. |

The user build's second type-10113 activity lasts 81.740s and encloses most
realization, so adding those durations would double count. There are 45 observed
file-transfer activities targeting cache narinfo URLs. This is not a census of
all HTTP traffic. Commands inside this nx run have peak concurrency 1; that says
nothing about other agents or parallel work inside Nix.

Load rises from 65.7 to 103.2 on 18 CPUs. During a five-second sample taken in
realization, 4,275 of 4,276 main-thread samples are blocked reading the daemon's
build RPC. That snapshot establishes a wait during those five seconds, not a
whole-run CPU percentage or proof of the daemon's reason for waiting. This is
a busy-host observation, not an isolated regression estimate.

## Warm and controlled checks

The existing pinned-config harness ran planning and checking three times with a
maximum starting load/CPU ratio of 2, identity checks and lock updates forbidden.
All six samples passed: planning median **0.178s** (0.129–0.350s), checking median
**0.354s** (0.129–0.985s), with no observed download/source-copy activities.
Existing caches were retained. This configuration identity precedes the tracing
config commit; comparing it to the changed-config rebuild is not an A/B test.

The normal correctness harness also completed 35 scenarios × three matched
traced/untraced pairs: 210 executions. Representative process-wall medians were
0.676s for an unchanged-input upgrade and 0.871s for the stubbed rebuild flow.
The sampled load rose 27.8→34.2. These controls simulate external work and have
wide scheduling/tracing deltas; they do not estimate Nix, Homebrew or network
latency, and cannot be compared directly to the older 31-scenario suite.

## Trace improvements and next priorities

1. **Keep routine evidence enabled.** New sessions now retain up to 20 private
   0600 traces, each capped at 8 MiB, under `~/.local/state/nx/traces`. A fresh
   session's generated trace was verified. Existing shells retain Home Manager's
   old session-variable marker; export `NX_TRACE_DIR` once in those shells.
2. **Preserve inner activity meaning.** Determinate uses type 10113 for several
   different operations. Real retained logs distinguish them with names such as
   `EvaluateFlakeDerivationOutput`, `CopySourcePath` and `QueryMissing`, plus
   typed payload targets. The collector now preserves names, `nix.installable`
   and `nix.source.path`; it excludes arbitrary payload, diagnostics and build
   log results. Nix identifies builder/post-build log results as 101/107 in its
   [logger protocol](https://github.com/NixOS/nix/blob/master/src/libutil/include/nix/util/logging.hh).
3. **Use the named trace to locate expensive repeats.** The fallback repeats a
   Nix build after the user-side build; 54.454s of inner root-side work is now
   visible. Exact attribution remains `nx-rs-mjgu`: separate evaluation, source
   checks and required activation before changing execution or estimating a
   speedup. Preserve the already-current shortcut and narrow sudo policy.
4. **Investigate daemon/load effects before parallel evaluations.** The long
   realization and the wait sample justify inspecting scheduling and daemon
   activity. They do not establish that more concurrency would help.

`perf_system.py --nix-activities TRACE` reports the longest completed activities
and a bounded set of unknown/incomplete rows, alongside command ownership.
Invalid IDs cannot form intervals; colliding IDs stay ambiguous for their
command. Old traces remain readable but their dropped names cannot be recovered.

Two read-only preflight probes stopped at an existing routing-lint inconsistency
for `packages/overlays/codex-acp.nix`, before issuing a Nix command. They are not
performance samples; `nx-rs-60fs` tracks that contract mismatch. The first probe
also left an explicitly desk-scoped timing record in normal history; it is
retained and excluded from operational aggregates. Later probes used private
timing files. The isolated config desk is retired; retained evidence is under
the standing repository's `.nx/perf/detailed-20261021/`.
